Village buildings real worldgen

Finds seeds with a village holding N smiths (tool/weapon/armorer) — by running Minecraft's actual generator, the only way to see inside a jigsaw village. Separate engine (MC 1.16.5), and slow.

Treasure casing real worldgen

A buried treasure writes the block it landed on into every air or water face around it — so it arrives already walled in. The main search cannot ask this: it runs on cubiomes, which has no surface rules and no decoration, so sand columns, ore and magma are absent from that engine rather than slow. Measured over 6 646 chests: sand 78%, gravel 18%, dirt 2.7%, stone 0.9% — and copper ore and magma ~0.015% each, about 6 600 chests scanned per expected hit.
Blocks per world decides how much of each world is actually examined. The finder reports only the first treasure in a seed, so this expands it to every treasure within that radius — 6 chests at 1 500, 1 431 at 20 000. For a rare casing that is the difference between searching a world and glancing at it.

Keep looking open-ended

The normal search walks seeds starting from the same place every time, so running it again re-scanned the same ground. This runs batch after batch on fresh seeds until it finds what you asked for, or you stop it. Uses the query currently in the box.

Fortresses inside each other piece-level

“Four fortresses close together” is the wrong measure, and it is the one a cluster search gives you. A fortress is up to 257 pieces sprawling 112 blocks from its start, and each is generated without knowing the others exist — so two starts 80 blocks apart do not sit near each other, they grow through each other. This counts intersecting piece pairs.

Exposed treasure real worldgen

A buried treasure chest sitting in open air — no digging. The chest is placed at the bottom of the sand column, so it is almost always covered or underwater; this needs a beach with essentially no sand over the stone. cubiomes cannot see it (no sand, no water), so real worldgen decides.
